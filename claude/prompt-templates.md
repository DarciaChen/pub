# E. 任務交辦 prompt 範本

版本 2026-07-12。用途：交辦 subagent（Claude Code）或直接當作 claude.ai 的任務開場。
規則：〔〕內是填空；「驗收條件」必須可機械檢查；「回報格式」必須限制輸出長度。
派 subagent 前自檢：三要素（目標動機/驗收/回報格式）齊了沒？缺一不派。

## 1. 搜尋／掃描型（找檔案、找程式碼、找呼叫點）
```
目標：在〔範圍：目錄或 repo〕找出〔具體目標：例如所有引用 kuromoji 的檔案〕。
動機：〔為什麼要找：例如準備統一升級 worker 版本〕。
做法限制:只讀不改;用 grep/glob 先縮小範圍再細讀,不要逐檔全文閱讀。
驗收條件：清單完整（用兩種以上關鍵字交叉搜尋過）；每筆含檔案路徑與行號。
回報格式：表格「檔案:行號｜上下文一行」，最後一行寫掃描了幾個檔案。不貼檔案全文。
```

## 2. 實作型（新功能、新工具、新檔案）
```
目標：建立〔交付物〕，功能是〔一句話〕。
動機：〔使用場景，誰在什麼時候用〕。
規格：〔輸入/輸出/介面語言/檔案格式；工具庫任務必守單檔 HTML 慣例〕。
不要做：〔明確排除項，例如：不要加登入功能、不要引入框架〕。
驗收條件：〔可檢查的行為：例如輸入「今日は」輸出「kyō wa」〕；
  執行過至少一組正常輸入與一組邊界輸入（空值/超長）並附結果。
回報格式：檔案路徑 + 測試輸入輸出對照 + 已知限制清單。程式碼不貼回對話，存檔即可。
```

## 3. 重構型（改既有檔，行為不變）
```
目標：重構〔檔案/模組〕，目的是〔可讀性/效能/去重複〕。
硬規則：動手前先備份（git commit 或另存 .bak）；對外行為不得改變。
基準：先記錄重構前的行為證據〔測試輸出/畫面/樣本結果〕。
驗收條件：重構後同一組輸入產生完全相同的輸出（附前後對照）；diff 範圍不超出約定檔案。
回報格式：改了哪些檔（檔案:行號區間）+ 前後行為對照 + 「行為無變化」的證據。
```

## 4. 研究型（查證、比較、彙整）
```
問題：〔要回答的具體問題，一句話〕。
用途：〔答案拿來做什麼決策——這決定深度〕。
來源要求：優先官方/原始來源；每個關鍵數字附來源；結論用【事實·來源】【推論】
  【未確認】三種標記（見 judgment-rubrics.md 研究節）。
範圍限制：最多〔N〕次搜尋；超過表示問題太大，回報並建議拆分。
驗收條件：直接回答了問題（不是給一堆背景）；標記完整；衝突來源有註明。
回報格式：先一段結論，再列證據。全文不超過〔N〕行。
```

## 5. 審查型（驗收別人/自己稍早的產出）
```
你是第一次看到這份產出的審查者，不要假設它是對的。
待審產出：〔路徑或內容〕。
原始需求與驗收條件：〔原文貼上——沒有這個就無法審查，先去要〕。
審查清單：(1) 需求逐條對照，漏了哪條;(2) 實際執行/fetch 驗證，不是看起來對;
  (3) 邊界輸入試一組;(4) 弱模型會誤讀的模糊句挑出來。
回報格式：結論一行（通過/不通過）+ 問題清單（每筆:位置、問題、建議修法、嚴重度
  高/中/低）。不通過就不要客氣。
```

## 通用附註
- 給便宜模型的任務，把「不要做什麼」寫得比「要做什麼」更詳細——弱模型的主要失效
  模式是過度發揮。
- 任何範本都可以加一行「完成前對照 claude/judgment-rubrics.md 第一部分第 2 條
  自檢完成度」。
