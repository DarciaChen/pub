# A. 快速診斷：本作業環境的三大漏洞與修法

版本 2026-07-12，由 Fable 5 制定。讀者：之後接手作業的任何模型（含 Haiku 級）。
規則寫法：每條含「現象 → 修法（可照做的步驟）→ 判準（違規訊號）」。

## 漏洞 1：大附件在長對話中重複計費（最漏 token）

現象：PDF、手冊、長文件掛在 claude.ai 對話裡之後，每一則新訊息都會重新處理整份附件。一份 50 頁手冊在同一對話問 20 題，等於付了 20 次全文處理費。

修法：
1. 收到大附件的第一個動作是「萃取」：把與當前任務相關的內容整理成不超過 200 行的 .md 摘要檔並存檔（claude.ai 存入 Project knowledge；Claude Code 存專案內 notes/ 資料夾）。
2. 之後所有問答引用摘要檔，不再引用原始附件。
3. 附件對話用完即止：話題轉換就開新對話，不在載著大附件的對話裡聊別的事。

判準：同一份附件在同一對話中被詢問超過 5 輪 → 違規，立即建摘要檔再繼續。

## 漏洞 2：長對話後期規格記憶腐化（最易出錯）

現象：對話越長，模型越容易「憑印象」寫出關鍵規格——ITEMS 欄位格式、Modbus 暫存器位址、部署參數、費率數字——而印象常是錯的或過時的。

修法：
1. 關鍵規格只有一個真相來源：repo 裡的檔案（入口見 CLAUDE.md 路由表）。對話記憶與檔案不一致時，以檔案為準。
2. 動手前先覆述：任何要寫入檔案、部署、或計算暫存器的任務，先原文引用規格檔的相關段落再執行。引用不出來就先讀檔，不准憑記憶動手。
3. Claude Code 對話超過約 30 輪、或開始答非所問 → 立即 /compact 或開新 session。claude.ai 對話出現同樣症狀 → 請 Darcia 開新對話並用「交接」產生摘要。

判準：回覆中出現任何未附引用來源的位址、欄位名、URL、參數值 → 視為未驗證，不得據以執行。

## 漏洞 3：產出未驗證即交付（最易「寫完」但沒「做對」）

現象：檔案部署後沒確認線上版本可用；程式改完沒實際跑過；查證類答案沒附來源。歷史教訓：CMS 檔 PDF 連結缺漏、工具部署後才發現壞。

修法（按任務類型三選一，照做即可）：
1. 部署類：走端點以回傳的 commit SHA 為完成依據（可用 GitHub API 覆核）；走 git 以 push 成功＋commit hash 為準。不要用 Pages URL 或 raw URL 驗證（CDN 快取會誤判）。無 commit 證據 = 任務未完成。
2. 程式類：必須實際執行一次。HTML 至少開啟檢查 console 無錯誤；腳本至少跑一組樣本輸入比對預期輸出。
3. 事實類：每個關鍵數字、日期、型號附上來源；查不到就寫「未確認」，禁止用合理猜測補完。

判準：交付訊息中缺少「驗證了什麼／怎麼驗／結果如何」三項 → 任務未完成，不得回報完成。
